# EcoCompliance API — instruções para agentes

API REST de governança ambiental (ESG). Atividade acadêmica FIAP (Java Advanced). Não há frontend neste repositório.

Responda ao usuário em português. Nomes de classes, métodos, mensagens de validação e de exceção também ficam em português, no estilo já usado no código (`listar`, `buscarPorId`, `criar`, `atualizar`, `excluir`).

O código vigente prevalece sobre este arquivo e sobre o README quando houver divergência.

## Stack

- Java 21, Spring Boot 3.3.4, Maven
- Spring Web, Data JPA, Validation, Security
- Oracle (`ojdbc11`) + Flyway (`V1` tabelas, `V2` dados, `V3` agendamentos)
- JWT (`jjwt` 0.12), BCrypt, SpringDoc OpenAPI 2.6
- Lombok 1.18.38
- Testes: JUnit 5, Mockito (`mock-maker-subclass`), `@WebMvcTest`

Pacote base: `br.com.fiap.ecocompliance`.

## Como rodar e testar

```bash
mvn test
mvn test -Dtest="LicencaServiceTest"
docker compose up --build
```

A API sobe na porta 8080. Swagger: `/swagger-ui/index.html`.

Banco via variáveis `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`. JWT via `JWT_SECRET` (Base64, chave HMAC). Não invente H2 nem outro dialeto: o schema é Oracle (`NUMBER`, `VARCHAR2`, `GENERATED BY DEFAULT AS IDENTITY`).

O `Dockerfile` empacota com `-DskipTests`. Isso não dispensa rodar `mvn test` antes de considerar uma mudança pronta.

Não há teste de integração com banco. Service usa `@ExtendWith(MockitoExtension.class)`. Controller usa `@WebMvcTest` + `@Import(SecurityConfig.class)`, `@MockBean` em `JwtService` e `UsuarioRepository`, e `@WithMockUser`. Listagem devolve `Page<T>`; asserts de JSON usam `$.content[0].campo`.

## Arquitetura

Fluxo obrigatório: controller → service → repository. Controller não contém regra de negócio e não devolve entidade JPA.

| Pacote | Responsabilidade |
|---|---|
| `controller` | HTTP, `@Valid`, status, delegação |
| `service` | Regra e `@Transactional` |
| `repository` | Spring Data JPA |
| `entity` | Modelo JPA, tabelas `TB_*` |
| `dto` | `record` de entrada e saída |
| `exception` | `ResourceNotFoundException` (404), `BusinessException` (400), `EmailAlreadyExistsException` (409), `DataIntegrityViolationException` (409) |
| `config` | `SecurityConfig`, `OpenApiConfig`, `DataInitializer` |
| `security` | `JwtService`, `JwtAuthenticationFilter` |

`spring.jpa.hibernate.ddl-auto=validate` e `open-in-view=false`. Schema novo entra só em migração Flyway. Não altere `V1`, `V2` ou `V3` já aplicadas; crie `V4__...sql` em diante.

## Domínio

`Empresa` é a raiz. Tudo o mais aponta para ela:

- `LicencaAmbiental` — status `ATIVA`, `VENCIDA`, `SUSPENSA`, `CANCELADA`. Validade não pode ser anterior à emissão. `GET /licencas/vencendo` lista validade nos próximos 30 dias; o status não é recalculado sozinho.
- `AuditoriaAmbiental` — risco `BAIXO`, `MEDIO`, `ALTO`.
- `EmissaoCarbono` — quantidade, fonte, data e unidade. Não existe campo de escopo GHG.
- `CompensacaoAmbiental` — tipo, descrição, quantidade e data.
- `AgendamentoReducaoCarbono` — status `PENDENTE`, `EM_ANDAMENTO`, `CONCLUIDO`, `CANCELADO`. Data fim posterior à data início. Status `CONCLUIDO` ou `CANCELADO` não pode ser editado.
- `Usuario` — não pertence a empresa. Roles `ADMIN` e `USER`.

CNPJ é único como texto, sem validação de dígitos verificadores.

`Empresa` faz cascade em licenças, auditorias, emissões e compensações. Agendamentos ficam de fora: excluir empresa que tenha agendamento viola a FK. Se for mexer nessa exclusão, cubra os agendamentos de propósito e teste o caso.

Relatório por empresa (`RelatorioService`) não inclui agendamentos. Indicadores globais (`IndicadoresService`) incluem. Não misture os dois sem pedido explícito.

## HTTP e segurança

Rotas sem prefixo `/api`. Paginação padrão: `@PageableDefault(size = 20, sort = "id")`. POST de criação devolve 201 com `Location`. DELETE devolve 204.

`SecurityConfig` é a fonte da autorização:

- `POST /auth/**`, `GET /ambiente` e `GET /up` públicos. `/ambiente` só devolve o nome da aplicação e o valor de `APP_ENV` (`local`, `staging` ou `production`). `/up` responde `{"status":"up"}` para o healthcheck do proxy.
- POST, PUT e DELETE dos recursos de negócio exigem `ADMIN`
- GET exige `USER` ou `ADMIN`
- Swagger e `/v3/api-docs` são públicos

Recurso novo precisa dos matchers em `SecurityConfig` e de teste de controller cobrindo 403 na escrita. Não use `@PreAuthorize` solto se o restante do projeto autoriza na cadeia de filtros.

`POST /auth/register` aceita a role no corpo e devolve JWT. Não alargue esse comportamento. Não copie o padrão de “o cliente escolhe a própria role” para endpoint novo. Não mova senha, `JWT_SECRET` nem usuário de banco para arquivo novo, log ou README.

Senhas só via `PasswordEncoder` (BCrypt). Não grave hash em SQL.

## Ao adicionar ou alterar um recurso

1. Entidade e, se o schema mudar, migração Flyway nova.
2. Repository.
3. `*RequestDTO` e `*ResponseDTO` como `record`, com Bean Validation na entrada.
4. Service com transação (`readOnly = true` nas consultas) e exceções do pacote `exception`.
5. Controller no mesmo estilo dos existentes.
6. Matchers em `SecurityConfig`.
7. `*ServiceTest` e `*ControllerTest` no mesmo estilo dos testes atuais.
8. Atualize o README só se o contrato HTTP ou o modo de subir a API mudou.

Mantenha o diff no escopo pedido. Não refatore camadas, não troque Oracle, não introduza MapStruct, ModelMapper ou módulo extra sem pedido.

## O que não fazer

- Expor entidade JPA no controller.
- Editar migração Flyway já existente.
- Ligar `ddl-auto` em `update` ou `create`.
- Abrir lazy loading fora da transação (`open-in-view` permanece `false`).
- Tratar regra de negócio com `ResponseStatusException` no controller; use `BusinessException` ou `ResourceNotFoundException`.
- Commitar segredo, `.env` ou credencial nova.
- Criar commit, push ou PR sem o usuário pedir.
